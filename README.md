# Allergoproba — самостоятельная регистрация пациента

Адаптивный HTML / CSS / JavaScript прототип без фреймворков. Для планшетов, телефонов и ПК. Белый фон без рамки, контейнера и декоративной подложки. Фирменный логотип клиники и Powered by Vivacell.

## Быстрый запуск

1. Распакуйте архив в отдельную папку.
2. Откройте файл `index.html` в Chrome/Edge/Firefox/Safari.
3. Для теста на телефоне, если компьютер и телефон в одной Wi-Fi сети: в папке проекта запустите `python -m http.server 8080` и откройте `http://IP_ВАШЕГО_ПК:8080/` на телефоне.

## Сценарии

**Самостоятельная регистрация:** приветствие → телефон → «На себя» → данные пациента → исследования → выбор процедуры забора биоматериала → анкета (пункты 1–5) → дополнительная анкета (пункты 6–11) → полное информированное согласие, подпись и добровольное подтверждение → проверка заявки → демо-результат. В отдельном `allergens.html` после проверки добавлен выбор «Сейчас / Позже» с Kaspi QR.

**Регистрация ребёнка:** приветствие → телефон → «На ребёнка/подопечного» → данные законного представителя и степень родства → отдельные данные ребёнка → исследования → выбор процедуры → анкета 1–5 → анкета 6–11 → информированное согласие, ручная подпись **представителя** → проверка заявки с двумя лицами → выбор «Сейчас / Позже» → Kaspi QR (при необходимости) → демо-результат.

### Проверка ИИН / имитация РПН

Все записи **исключительно локальные, придуманные для тестирования**. Подключения к РПН нет.

- Законный представитель / самостоятельный пациент: `123456789012` → «Косилов Данил Алексеевич», «22.12.2005».
- Ребёнок: `160504500777` → «Косилов Арсен Данилович», «04.05.2016» (**вымышленный ребёнок** для работы прототипа).
- Данные подставляются автоматически через небольшую задержку после ввода 12 цифр. ИИН для представителя и ребёнка не могут совпадать.
- Номер из демонстрации — **не подтверждение существования реального человека в регистре** и не проверка формата/контрольной суммы ИИН.
- Можно выбрать сценарий иностранного гражданина и вручную указать имя и дату рождения. Эти сведения тоже не проверяются в государственных системах.
- После получения данных необходимо поставить отметку «Данные верны». Для законного представителя также нужно выбрать степень родства.

### Анкета и процедуры

- На отдельном шаге пользователь отвечает «Да / Нет» по забору биоматериала.
- 11 пунктов анкеты, соответствующих предоставленному референсу, в двух частях (1–5 и 6–11). Отмеченный чекбокс раскрывает поле уточнения. В пункте 10 подробности обязательны, если он отмечен.
- Дополнительное свободное поле для медицинских особенностей и замечаний по подготовке. Если пункт 11 не выбран, отображается уведомление сообщить о подготовке медперсоналу.
- Все введённые ответы сохраняются при переходах назад/вперёд и при изменении языка **в пределах текущей открытой страницы**.

### Информированное согласие

- 10 полнотекстовых пунктов на **одном экране, без раскрывающихся блоков**, точно по тексту, предоставленному заказчиком в запросе.
- Подпись рисуется мышью, пальцем или стилусом на Canvas; доступны очистка и подтверждение отдельным чекбоксом.
- Для перехода к итоговой проверке требуется реальная нарисованная линия и чекбокс согласия. Согласие не сохраняется на сервере.
- Интерфейс переключается между RU, KZ, EN. **Текст согласия и 11 пунктов анкеты оставлены на русском**, поскольку утверждённые медицинские/юридические переводы не предоставлены. В интерфейсе для KZ/EN это обозначено.

## Ограничения и подготовка к внедрению

**Это интерактивный демопрототип, не медицинская информационная система.** Он не обращается к реальному РПН, не регистрирует заявки, не хранит персональные данные и подпись на сервере и не создаёт юридически действительное электронное согласие. Демо-номер заявки создаётся исключительно для UI.

Перед внедрением необходимо: согласовать официальные документы/переводы и клинические анкеты, проверить правовое основание и актуальность реквизитов формы, реализовать серверную интеграцию с реальными API (с разграничением прав), запись заявок, доказуемое подписание документа (идентификация, версия текста, журнал событий, дата/время, PDF, защищённое хранение) и требования к защите персональных данных. При подготовке к исследованию отмену лекарств нельзя рекомендовать без согласования с лечащим врачом; в демо приводится только текст заказчика. После 10 минут бездействия прототип очищает данные из памяти страницы.

## Отдельная страница с выбором аллергенов

**`allergens.html`** — самостоятельный экран входа во второй сценарий, использует ту же базовую логику, стиль, формы, проверку ИИН, разделение на взрослого/ребёнка, анкету, согласие и подпись.

- Первый сценарий: `index.html` — выбор **вида исследования**, как прежде.
- Дополнительный сценарий: `allergens.html` — выбор **конкретных аллергенов из каталога** (вместо вида исследования).
- В каталоге можно искать название, переключать категории, выбирать несколько аллергенов и убирать выбранные. Перед переходом дальше обязателен минимум один аллерген. Выбранные позиции отображаются в финальной проверке заявки.
- Между сценариями можно перейти по ссылке на приветственном экране.
- Локальный каталог вынесен в **`allergens-catalog.js`**. Его позиции *демонстрационные* и служат только для интерфейса. Для реальной ИС список, категории, доступность, идентификаторы и цены должны приходить из согласованного справочника сервера; **не считайте демо-каталог официальным перечнем исследований**.
- Оба флоу работают при открытии HTML из папки без интернета. Состояния не пересекаются и не отправляются на сервер.
- RU/KZ/EN интерфейс каталога переведён. Медицинская анкета и полный текст согласия остались на русском, как в исходном проекте.


## Новый этап оплаты (только в allergens.html)

Только на странице **`allergens.html`** после проверки заявки и нажатия «Зарегистрировать» открывается выбор способа оплаты. В **`index.html`** оплата отсутствует.

- **Оплатить позже**: регистрация завершается с демонстрационным статусом «Не оплачено · оплата позже».
- **Оплатить сейчас**: пользователь переходит на экран выбора способа оплаты, выбирает **Kaspi QR**, после чего появляется изображение QR из файла `assets/kaspi-qr.png` (приложено заказчиком).
- Можно вернуться назад, либо выбрать «Оплачу позже».
- При завершении сценария оплаты через Kaspi **не выставляется статус «Оплачено»**. Отображается только «Ожидает подтверждения оплаты», даже если пользователь отсканировал QR.
- Это статический QR из изображения. Прототип показывает демонстрационную сумму выбранных аллергенов, но **не умеет передавать эту сумму в статический QR**, не получает данные о получателе платежа, не может создавать индивидуальный платеж, проводить возврат или проверять оплату. QR из вложения необходимо проверить перед использованием с реальными платежами.
- Для запуска в production нужны API создания заявки, расчёта цены, генерации платежа, проверки статуса и серверного подтверждения/идемпотентности; нельзя считать факт нажатия кнопки подтверждением платежа.
- Все данные и статусы являются только локальной демонстрацией.


## Разделение флоу и демонстрационные цены (23.11.2026)

- `index.html`: регистрация с выбором типа исследования, **без экрана оплаты**. После проверки и регистрации сразу выводится успешная демо-заявка.
- `allergens.html`: выбор аллергенов с **демонстрационной ценой 5 000 ₸ за позицию**, сумма автоматически пересчитывается при выборе и удалении аллергенов и показывается в каталоге, проверке заявки, экранах оплаты и завершении.
- В `allergens-catalog.js` у каждой позиции есть поле `priceKzt: 5000`. Для изменения тестовой цены исправьте это поле. Если поле отсутствует, применяется 5000 ₸ по умолчанию.
- Тестовые цены НЕ являются официальным прайсом Allergoproba и не подтверждены лабораторией.
- Сумма не передаётся в Kaspi: QR предоставлен в виде статического изображения и **не привязан** к вычисленной сумме. Проверяйте получателя и сумму до реального платежа.
- Для продуктивной версии: серверный каталог цен, расчёт суммы, динамическая платёжная ссылка/QR, API статусов и подтверждение платежа.
